# Instructions for AI agents working on this repo

You are helping someone teach their local `nlsh` model (English -> one PowerShell 5.1 command line) about
their own tools, or retrain it. Humans: see `docs/index.html` for the illustrated version of this.

## Repo map
- `nlsh/nlsh.psm1` - runtime. Hooks PSReadLine Enter: a line `ai <english>` is sent to Ollama model `nlsh` and replaced by the reply.
- `data/STYLE.md` - **the canonical command style. Read it before writing any data.** Consistency matters more than cleverness: a 1.5B model learns one style.
- `data/hand/*.jsonl` - hand-written pairs `{"q": "...", "cmd": "..."}`. Add new files here (e.g. `data/hand/tools_mytool.jsonl`).
- `data/gen/templates.jsonl` - generated by `scripts/gen_templates.py` (value variety for fd/rg). Don't edit by hand.
- `data/eval.jsonl`, `data/eval_tools.jsonl` - held-out benchmark with accepted answers. Never copy these into training data.
- `retrain.ps1` - one command: build dataset -> LoRA fine-tune -> GGUF -> `ollama create`.
- `scripts/probe.py <model>` - exact-match benchmark. `scripts/tool_probe.py <model>` - eyeball answers for many tools.
- `SUPPORTED_TOOLS.md` - what the shipped model is trained on. Update it when you add a tool.

## Adding a tool (the usual task)
1. Confirm the tool is installed: `Get-Command <tool>`. Read `<tool> --help` and the help of each subcommand you use.
   Every flag in your data must exist in the installed version. Never run commands that change state, log in, or download.
2. Write 20-40 examples to `data/hand/tools_<name>.jsonl`:
   - ~60% casual English that does NOT name the tool when context makes it obvious ("show my open PRs" -> `gh pr list`),
     ~25% naming the tool, ~15% terse/typo'd/Linux-brained.
   - Use the user's literal values (file names, ports, URLs). Single-quote patterns; no `&&`, `||`, `??` (PowerShell 5.1).
   - Avoid embedded double quotes in arguments to native exes (PS 5.1 mangles them); prefer single quotes.
   - `fd -x/-X` only run real executables, never cmdlets: pipe to cmdlets instead (`fd -e tmp | Remove-Item`).
   - If the tool replaces a default (e.g. `eza` instead of `Get-ChildItem`), also add a rule to `data/STYLE.md`
     and rewrite conflicting examples in other `data/hand/*.jsonl` files, or the model gets mixed signals.
3. Validate (must print nothing but the counts):
   ```powershell
   Get-Content data\hand\tools_<name>.jsonl | ForEach-Object {
     $o = $_ | ConvertFrom-Json; $e = $null
     [void][System.Management.Automation.Language.Parser]::ParseInput($o.cmd, [ref]$null, [ref]$e)
     if ($e) { "PARSE ERROR: $($o.cmd)" } }
   ```
   and check no `q` duplicates one in another `data/hand` file or in `data/eval*.jsonl`.
4. Add 2-5 held-out cases with `accept` lists to `data/eval_tools.jsonl` (queries NOT in training data).
5. Run `.\retrain.ps1` (about 20 min on an RTX 5060 Ti; needs an NVIDIA GPU with >= 8 GB; run it in the background). It prints the benchmark at the end.
6. Report the before/after benchmark numbers and update `SUPPORTED_TOOLS.md`.

## Don'ts
- Don't change the prompt format in `train/train.py` without changing `ollama/Modelfile` to match (plain ChatML, no system prompt).
- Don't commit `train/out`, `*.gguf`, `train/.venv` or `train/llama.cpp` (all git-ignored).
- Don't "fix" the benchmark to match model output; fix the training data.
- Don't lower exact-match standards by adding sloppy answers to `accept` lists; only add genuinely equivalent canonical forms.
