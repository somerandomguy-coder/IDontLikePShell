Train your own English → PowerShell model

nlsh is a tiny local model that turns plain English into a PowerShell command at your prompt. This guide shows how to teach it the tools you use and retrain it on your own GPU.

How it works

1 · You typeai + English, then Enter
2 · PSReadLineEnter hook catches lines starting with ai
3 · Ollamafine-tuned 1.5B model, kept loaded on the GPU
4 · Your promptline is replaced by the command; nothing runs yet

The model is Qwen2.5-Coder-1.5B with a LoRA fine-tune on about 3,400 example pairs that cover fd, rg, PowerShell and about 40 common CLIs. Answers come back in about 50-200 ms. Every other line you type runs exactly as before.

Quick start

  1. Clone the repo and open PowerShell in it.
  2. Train and register the model. The first run also builds the training environment (about 3 GB of downloads): 
    .\retrain.ps1
  3. Hook it into your profile: 
    .\install.ps1
  4. Open a new terminal and try ai find all pdf files.
Not happy with an answer? Press Up to get your ai … line back and press Enter again. Asking the same thing twice in a row gives a different answer.

Teach it a tool

Training data is plain JSON Lines: one English request and the exact command you want back.

{"q": "show my open PRs", "cmd": "gh pr list --author '@me'"}
{"q": "make a venv", "cmd": "uv venv"}
{"q": "files starting with gelato, this folder only", "cmd": "fd -t f -d 1 '^gelato'"}
  1. Read data/STYLE.md. It sets one canonical form for quoting, flag order and which tool to prefer. A small model learns best from data that always does things the same way.
  2. Write 20-40 examples in a new file such as data/hand/tools_eza.jsonl. Mix the phrasing:
    • ~60% casual English that doesn't name the tool ("list files with icons")
    • ~25% that names it ("eza tree 2 levels")
    • ~15% terse, typo'd or Linux-style ("ls -la")
  3. Check every flag against <tool> --help for the version you have installed. Wrong flags in the data become wrong flags in the answers.
  4. Replacing a default? For example, to get eza instead of Get-ChildItem, add a rule to STYLE.md and rewrite the old examples that contradict it. Otherwise the model sees both answers and picks between them at random.
  5. Add 2-5 held-out test cases to data/eval_tools.jsonl with the answers you'd accept. Don't put these in the training files.
PowerShell 5.1 gotchas the data must respect: no && or ||. curl is an alias for Invoke-WebRequest, so write curl.exe when you mean curl. Double quotes inside arguments to native programs get mangled, so prefer single quotes. fd -X can only launch real programs; to use a cmdlet like Remove-Item, pipe into it instead.

Let an AI write the data

Writing examples is the slow part, and any capable coding assistant can do it. Point it at AGENTS.md, which covers the repo layout, the rules and how to validate. Or paste this prompt:

Read AGENTS.md and data/STYLE.md in this repo. Then add training data for the tool
<TOOL> to data/hand/tools_<TOOL>.jsonl: about 30 {"q","cmd"} pairs covering the
subcommands I actually use: <LIST THEM>. Check every flag with `<TOOL> --help`
(read-only, don't run anything that changes state). Validate the file as AGENTS.md
describes, add 3 held-out cases to data/eval_tools.jsonl, then run .\retrain.ps1
and report the benchmark before and after.

Data that one model generates and another model checks against the real --help output works well. Before training, skim 10 random lines yourself anyway.

Train

.\retrain.ps1                                        # defaults: 1.5B, 3 epochs, model name nlsh
.\retrain.ps1 -Base Qwen/Qwen2.5-Coder-0.5B-Instruct -Name nlsh-small

What it runs:

  1. gen_templates.py and build_dataset.py merge your data. Hand-written examples are counted twice, and 8% of them are held out for scoring.
  2. train/train.py runs the LoRA fine-tune (rank 32, all projection layers, bf16, loss on the answer only) and merges the result into the base model.
  3. llama.cpp's converter exports a q8_0 GGUF, and ollama create registers it.
  4. The benchmark runs and prints the score.

With the shipped data (about 5,200 training rows after hand-written examples are doubled), 3 epochs take about 16 minutes on an RTX 5060 Ti (16 GB). The whole script takes about 20 minutes. Training time grows linearly with the amount of data.

Evaluate

python scripts\probe.py nlsh           # exact-match on data/eval*.jsonl, with latency
python scripts\tool_probe.py nlsh      # 2-3 questions per installed tool, judge by eye

Exact match is strict: Sort-Object WS and Sort-Object WorkingSet both work, but only one is in the answer list. Use the score to compare one training run against the next, not as a measure of absolute quality. When a tool scores badly, add training data for it. Don't loosen the answer lists to make the score go up.

Pick a base model

BaseGGUF sizeUse when
Qwen2.5-Coder-0.5B-Instruct~0.5 GBno GPU, or very old hardware; expect more mistakes on multi-step requests
Qwen2.5-Coder-1.5B-Instruct (default)~1.6 GBbest balance; about 100 ms per answer on a midrange GPU
Qwen2.5-Coder-3B-Instruct~3.3 GByou have VRAM to spare and want better multi-step pipelines

Any Hugging Face causal LM with ChatML tokens and llama.cpp support should work, though only the Qwen2.5-Coder models above have been tried here. If you switch to a model family with a different chat format, update prompt() in train/train.py and the TEMPLATE in ollama/Modelfile to match.

Troubleshooting

SymptomFix
Beep, nothing happens; title bar says "Ollama is not running"Start the Ollama app or run ollama serve.
unsupported MLX architecture from ollama createRecent Ollama can't import safetensors for this model type; use the GGUF that retrain.ps1 builds.
'list' object has no attribute 'keys' in the converterThe tokenizer was saved by a newer transformers. retrain.ps1 copies the base model's tokenizer files back in for you.
Model ignores your new toolNot enough examples, or other examples contradict them. Search data/hand for the old way of doing it.
Answer is right but the command failsUsually PS 5.1 quoting, or fd -X with a cmdlet. Fix the examples, not the runtime.
CUDA out of memory while trainingLower the batch size (.\retrain.ps1 -BatchSize 8) or pick a smaller base model.
